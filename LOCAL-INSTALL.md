# Локальная установка в ESPHome через SMB

Эта копия предназначена для уже установленного ESPHome Device Builder: это **внешние компоненты ESPHome**, а не интеграция `/config/custom_components` и не самостоятельное дополнение Supervisor. Готовая прошивка в архив не входит — её надо собрать из вашего YAML для вашей ESP32.

## 1. Резервная копия

Сохраните на компьютере вашу текущую папку `config/esphome/ESPHome-Ready4Sky` и собственные YAML-конфигурации ESPHome. Особенно важно сохранить свои изменения, которых нет в данной копии. Архив создан из опубликованного upstream, а не из ваших файлов: доступа к вашему SMB у автора исправлений не было.

## 2. Замена компонентов

1. Распакуйте архив на компьютере. Внутри будет папка `ESPHome-Ready4Sky`.
2. По SMB откройте `config/esphome/ESPHome-Ready4Sky/`. Переименуйте существующую папку `components`, например в `components-backup`, либо перенесите её в безопасное место.
3. Скопируйте **папку `components` целиком** из архива в `config/esphome/ESPHome-Ready4Sky/`. Не копируйте только два `__init__.py`: движок и все связанные драйверы изменены вместе. Проверьте, что получились, например:

   ```text
   config/esphome/ESPHome-Ready4Sky/components/ready4sky/__init__.py
   config/esphome/ESPHome-Ready4Sky/components/ready4sky/commands.cpp
   config/esphome/ESPHome-Ready4Sky/components/skycoffee/__init__.py
   ```

   Не должно получиться `.../components/components/...`. Не удаляйте и не заменяйте ваши `secrets.yaml`, YAML устройств и другие личные файлы. Документацию, `tests` и `examples` копировать на Home Assistant для работы необязательно.

## 3. Проверьте источник в своём YAML

Если YAML устройства расположен прямо в `config/esphome/`, путь к вашим локальным компонентам должен быть таким:

```yaml
external_components:
  - source:
      type: local
      path: ESPHome-Ready4Sky/components
```

Путь `path` задаётся относительно каталога самого YAML; если YAML находится в другой папке, исправьте путь соответственно. Если в YAML уже есть `external_components`, не создавайте второй одноимённый блок: измените источник Ready4Sky внутри существующего списка, сохранив остальные источники. Git-ссылка на исходный репозиторий вместо локального пути подтянет прежний код. Если используете список `components:`, включите туда и `ready4sky`, и необходимые драйверы, например `skycoffee`.

Для ориентира конфигурация с одной кофеваркой дана в `examples/coffee-in-esphome-root.yaml`. Это **шаблон**, не готовая к прошивке конфигурация: примерные MAC, модель и секреты нужно заменить. Обычно достаточно перенести недостающие разделы в ваш существующий YAML, а не заменять весь файл. Сохраните вашу плату, Wi-Fi, ключи, OTA и настройки API.

## 4. Проверка и обновление прошивки

1. Откройте конфигурацию вашей ESP32 в ESPHome Device Builder. Проверьте, что она использует ESP32 с поддержкой BLE и `framework: type: esp-idf`; выполните **Validate**.
2. После замены компонентов очистите старые временные файлы сборки устройства через меню ESPHome **Clean Build Files**, либо командой `esphome clean <ваш-yaml>` в среде ESPHome. Это важно, в частности, для нового `ready4sky/commands.cpp`. Затем соберите вашу конфигурацию. Не используйте `clean-all`: он удаляет общие кеши toolchain.
3. Если проверка и сборка прошли, установите только свою прошивку на нужную ESP32 обычным для вас способом. Держите резервную копию прежней прошивки/конфигурации для отката. **Не прошивайте** тестовые YAML из `tests/`.
4. Откройте логи ESPHome и проверьте обнаружение, подключение, первое обновление состояния, ручное включение/выключение, потерю и восстановление связи. Не оставляйте прибор без присмотра на первых проверках.

При ошибке сохраните текст лога **без паролей и токенов**, точную модель прибора и версию ESPHome: вывод `Validate`/сборки покажет запрещённую опцию или несовместимую конфигурацию.

При разрыве связи состояния большинства приборов могут остаться последними полученными значениями — не считайте их подтверждением текущего состояния. `skysmoke` отдельно помечает данные недоступными, но не является средством пожарной безопасности. Безопасность и устойчивость на ваших устройствах аппаратно не проверены. Подробнее: [README.md](README.md), [TESTING.md](TESTING.md).
