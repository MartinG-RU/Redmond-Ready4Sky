# Результаты и воспроизведение проверок

## Версии

* ESPHome **2026.10.1**, Python 3.13. На 1 ноября 2026 года это актуальный стабильный выпуск ESPHome; см. [страницу выпусков](https://github.com/esphome/esphome/releases/tag/2026.10.1).
* Тестовая цель — `esp32dev` (обычный ESP32), framework ESP-IDF.
* Два toolchain: нативный ESPHome/ESP-IDF **5.5.6** и PlatformIO/ESP-IDF **5.5.5**. Для каждого собрана прошивка с девятью драйверами.
* Собственный сервер пользователя, его версия Home Assistant и реальные устройства не проверялись. Сборка не доказывает работу всех моделей, настроек и конфигураций. Arduino, ESP32-C2/C3/S3 и другие платы аппаратно и компиляцией не проверялись; для C3 проверена только генерация настроек лимита BLE.

## Проверки

```sh
python -m pip install 'esphome==2026.10.1' pytest
python -m pytest tests/test_schema.py -q
bash tests/native/run.sh
esphome compile tests/all-drivers-native.yaml
esphome compile tests/all-drivers.yaml
```

На подготовленной копии получено:

* **36 успешных pytest-проверок** схем и генерации. Пройдена генерация для 98 принимаемых строк моделей; остальные 5 вариантов неподтверждённых нагревателей проверены на явный отказ. Это не 98 скомпилированных прошивок: компиляционная матрица содержит по одному представителю каждого из девяти драйверов. Проверены также конфликт BLE-компонентов, повтор MAC, ограничения сканирования и некоторые неподдерживаемые настройки кофеварки, чайника и обогревателя. Оба шаблона YAML прошли валидацию с тестовыми секретами.
* **Два host-теста C++ с ASan/UBSan:** реальные `commands.cpp`, `skyplug.cpp`, `skycoffee.cpp`, `skysmoke.cpp`, а отдельно `ready4sky.cpp` с программным имитатором ESPHome/ESP-IDF. Проверены корректность данных очереди и порядок команд, приоритет OFF даже при старом состоянии «выключено», повторная проверка блокировки перед отложенным ON, обработка коротких кадров, тайм-ауты, некоторые сценарии offline/reconnect датчика, копирование уведомлений, потеря BLE-событий, ограничение мониторинга, обработка устаревших событий и watchdog отключения. Для первого теста выключена только проверка UBSan `vptr` из-за упрощённой RTTI заглушки движка; второй проходит с полной UBSan.
* **Две успешные сборки** одной тестовой матрицы из девяти драйверов — нативной цепочкой и PlatformIO. Для обычной ESP32 обе сгенерировали `CONFIG_BTDM_CTRL_BLE_MAX_CONN=9` и `CONFIG_BT_ACL_CONNECTIONS=9`. Матрица имеет вымышленные MAC, SSID и пароль: **не прошивайте её**.

Симулятор не моделирует реальный BLE-радиоканал, многозадачность Bluedroid, фактические задержки или все последовательности ответа. Подсветка чайника, все протокольные варианты моделей, часы/DST, безопасность, многосоединения и восстановление связи нуждаются в проверке с устройствами. Тесты не сертифицируют датчик дыма и не подтверждают безопасность нагревателей.

Правила локальных относительных путей описаны в [официальной документации ESPHome](https://esphome.io/components/external_components/). Практическая установка по пути пользователя — в [LOCAL-INSTALL.md](LOCAL-INSTALL.md).
