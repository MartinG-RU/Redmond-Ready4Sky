# Использование своего репозитория GitHub в ESPHome

Этот репозиторий — **внешние компоненты ESPHome** для уже установленного ESPHome Device Builder. Это не отдельный аддон Home Assistant и не `custom_components`.

## Для вашей конфигурации SkyCoffee

После создания публичного репозитория скрипт публикации покажет его точную ссылку и готовый блок `external_components`. В существующем файле `Redmond Skycoffee.yaml` замените **только** имеющийся блок `external_components` на показанный скриптом. Для ориентира формат следующий, но `YOUR-ACCOUNT` и имя репозитория необходимо заменить на ваши:

```yaml
external_components:
  - source: github://YOUR-ACCOUNT/ESPHome-Ready4Sky@main
    components: [ready4sky, skycoffee]
    refresh: 1h
```

Не вставляйте второй одноимённый блок. Если у вас уже есть другие внешние компоненты, сохраните их отдельными элементами в том же списке `external_components`. Остальные разделы вашей конфигурации — плата ESP32, Wi-Fi, MAC-адрес, модель, API, OTA, время и управления — не удаляйте и не заменяйте примерами из репозитория. Указание исходного репозитория `KomX/ESPHome-Ready4Sky` вместо **вашего** загрузит исходный код, а не эту исправленную копию.

1. Убедитесь, что указаны ваши Wi-Fi и Bluetooth MAC; примеры не содержат реальных параметров прибора.
2. В ESPHome выполните **Validate**. После смены источника очистите **Clean Build Files**, затем соберите вашу конфигурацию и установите прошивку на ESP32 обычным способом. Не прошивайте конфигурации из `tests/`.
3. Проверьте BLE и включение/выключение прибора под наблюдением. Эта версия не испытывалась на физической ESP32 или кофеварке.

`refresh: 1h` означает, что ESPHome периодически проверяет исходный Git-репозиторий; это **не** автоматическая прошивка ESP32. Ветка `main` может меняться, поэтому новые сборки могут получить изменения. Для воспроизводимости можно вместо `main` указать проверенный тег или хеш коммита. `Clean Build Files` также полезно при изменении C++ файлов, в том числе при первом переключении на этот комплект.

Публичный репозиторий читается без входа в GitHub со стороны ESPHome. Для закрытого репозитория нужно отдельно настроить Git-аутентификацию **в среде самого ESPHome**; доступ браузера или Codespaces этого не гарантирует. Учтите, что ESPHome может сохранять Git-учётные данные в своём каталоге `.esphome`; не публикуйте токены и `secrets.yaml`.

Другие поддерживаемые драйверы и ограничения перечислены в [README.md](README.md), проверенные сборки — в [TESTING.md](TESTING.md). В частности, `skyoven` не реализован, поддержка некоторых нагревателей ограничена; управление по BLE не заменяет аварийное отключение. В оригинальном upstream отдельный файл лицензии не обнаружен — перед публичным распространением проверьте свои права.
